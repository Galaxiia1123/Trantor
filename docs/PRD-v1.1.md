# 川陀 v1.1 产品与验收基线

2026 年 11 月 3 日。v1.1 面向准备场景、启动推演和回看结果的人。原始 [v1.0 PRD](PRD-v1.0.md) 保留为历史依据。新版本延续独立主体、跨层影响、统一逻辑窗口、主体自主决策、世界后果校验和可追溯报告。

## 从背景或文稿开始

一段背景或一份 Markdown 规划文稿均可作为完整入口。目标可以从文稿中识别。有足够信息时，用户审阅一页摘要后即可启动。摘要说明研究什么、谁参与、运行多久、哪些设定仍为假设。可选的问题与低频技术选项放在高级设置。

## 补全与来源

每次准备都检查场景边界、主体与偏好、归属、关系、已定义状态、适用规则、时间和关键缺口。先复用材料。公开可检索事实、用户意图、模拟设定分别处理。只检索影响开局的公共问题，检查相关性、发布或适用时间与来源，保留查询、来源链接、检索时间、摘录及其支持的定义。虚构设定以文稿为准。公开检索失败保留未知，未决的关键冲突或意图集中交给用户。

## 一个模型和独立上下文

一次配置提供商、API 和模型。解析、决策、世界、可选记忆处理和报告均使用这份配置。凭据由服务端保管。每个主体只接收本主体获准看到的状态、资料、记忆和消息。调用失败要有可见状态。

## 层级与关系

子主体可以直接归属上级。仅在至少两个内部主体确有互动需求时保留博弈子系统。去除分类容器时保留所有主体、真实父子关系、状态与跨层边。

每个有向关系单独保存文字描述，可以包含渠道、作用范围、条件、限制及材料依据。反向边单独配置。新推演由描述参与判断，目标保有决策权。变更保留版本、依据及适用边界。旧运行保留当时的数值权重，旧数字本身不足以推断新关系的机制。

## 状态与长期记忆

引擎维护用户定义的客观状态。观察界面默认显示按主体组织的状态文字，数值、单位、未知值与来源可展开。主体的状态文字从同一提交快照按可见权限派生，金额、期限等决定可行性的数字保留在句中。未定义字段不产生默认值或评分。

记忆由稳定档案、当前处境、近期原文、历史摘要、持续事项和少量按需检索构成。承诺的当事人、条件、截止时间和履行状态可追溯。压缩和检索均限定在主体可见范围内，完整日志独立保存。衡量总输入、输出、调用次数与关键信息保留率，包含压缩本身的成本。

## 运行与观察

场景 AI 在用户已有设定内提出运行窗口、调度、记忆和异常处理方案。用户显式设置优先。开局前保存实际采用的方案，可展开修改。引擎统一结算，校验失败按已选策略修正、重试或暂停。主体表达、消息、世界结果和报告优先保留决定、必要依据、条件及变化，长度随任务复杂度调整。

观察页按时间呈现正在发生的行动、关键互动、客观后果与依据。暂停、继续、结束和历史回看就近提供。原文、数值、调用与诊断信息按需展开。模型未配置、运行失败、静态回放和真实调用如实区分。

## 贯穿验收

导入含多层主体、跨层文字关系、已知金额和带条件承诺的 Markdown 文稿。验证已有时间设定被沿用、不产生单成员空壳、不对完整设定发起无用搜索。另以有可核验公开缺口的场景验证检索、引用和搜索失败路径。在同一模型上运行到记忆压缩后，检查知情方仍能找回承诺、条件和期限，未获告知者没有该信息。对照界面状态、主体输入、底层字段和引用的提交记录，再生成可回溯报告。

安装、示例、配置和限制应与真实入口一致，具备向 GitHub 交付的条件。公开发布是独立操作。记忆阈值、检索条数与错误重试次数属于可检验、可调整的工程选择。
