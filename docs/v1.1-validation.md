# Trantor v1.1 验收记录

## 两个可直接回看的案例

**芦湾维修押保协商**使用虚构文稿和真实模型运行两个窗口。两家机构共做出四次决定，送达四条定向消息。维修社提出 200 万元有条件担保，最终提交显示，签字复核函未送达，实际到账仍为 0 万元，复议状态为“待材料”。工作台的“阅读这次推演”保留了场景、发言、被拒绝的结算提案和最终字段值。报告为公开节选，点击记录编号可核对原文。[案例文稿](../examples/conditional-review.md)

**潮汐港的窗口期**提供可复现的九窗脚本回放。五个不同层级的主体各有自己的观察。工程师可以直接联系市议会，议会保留复议决定权。第八窗的审批状态可以改变，资金缺口仍为 2000 万元。回放和浏览器验收使用预设应答，可在没有模型密钥的环境中运行。[案例文稿](../chuantuo/templates/tidal-port.md)

同一潮汐港设定也完成过真实模型的九窗验收。第一次运行发现，居民能通过转发收到私下代号。依据文稿补上消息的传播范围后，第二次运行记录了 90 次主体决定与 106 次投递，居民收到的消息和 18 次决策输入中均未出现该代号。固定短语校验能查出已登记的原文，对改写后的语义仍需核对上下文。

## 如何复查

在项目目录的 Python 3.12 虚拟环境中运行 `python -m pip install -e ".[test,browser,benchmark]"` 安装测试依赖。Python 与 JavaScript 用例检查字段约束、跨层影响、记忆、信息隔离、失败恢复和报告引用。两套浏览器检查分别覆盖当前工作台及历史项目界面。浏览器使用独立资料目录和本机测试接口。

运行 `python scripts/measure_v11_memory.py`，可用同一套脚本输入比较全历史与受限记忆在 9 窗和 36 窗的文本量与参考分词数。运行 `python scripts/verify_install.py --browser`，可检查新环境安装的发行包能否启动、推演、核验日志并打开报告。

上述案例只说明指定材料、观察权限和窗口内的模拟结果。真实模型重跑时，其发言、行动和结算提案可能不同。
